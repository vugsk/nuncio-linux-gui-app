# nuncio

Техническое имя репозитория — `nuncio-linux-gui-app`; публичное имя появится
к выпуску 1.0.0.

**Неофициальный клиент Telegram под Linux, использует Telegram API** (свой `api_id`,
условия: https://core.telegram.org/api/terms). Не связан с Telegram и не одобрен им.

Три слоя в одном процессе: интерфейс и домен (Rust + Slint), сеть (Go, c-archive),
крипто-ядро MTProto (C++, статическая `libtgcrypto.a` на OpenSSL).

## Что умеет

- **Вход:** по QR-коду или номеру телефона, облачный пароль, регистрация; сессия
  зашифрована, ключ — только в системной связке (Secret Service).
- **Чаты:** список с папками и архивом, поиск (локальный и на сервере), поиск по чату
  с фильтрами; история с прокруткой по хронологии; ответ, пересылка, правка, удаление,
  закрепление; форматирование и эмодзи в поле ввода; очередь отправки без сети.
- **Вложения:** фото и альбомы, файлы, голосовые, видео и видеосообщения (свой
  статический FFmpeg), GIF, превью ссылок, опросы; окно просмотра; отправка через
  системный диалог и вставку из буфера; вкладки общих медиа в «Сведениях».
- **Стикеры:** статичные, видео (WebM с прозрачностью) и анимированные (TGS,
  через ThorVG) — в ленте без пузыря; панель в поле ввода (недавние и
  установленные наборы), отправка щелчком.
- **Система:** уведомления D-Bus со своим звуком и громкостью, значок в трее со
  счётчиком, темы (системная, тёмная, светлая, своя из файла — на лету), размер
  текста, русский и английский, прокси (SOCKS5, MTProxy), «Графика: GPU» (Skia).
- **Условия API:** рекламные сообщения в каналах и у ботов (одной строкой),
  самоуничтожающиеся вложения без сохранения и кэша.

**Статус:** до первого выпуска (0.x): основное готово, идёт отделка. Проверено
на Arch Linux (Wayland и X11, масштаб 1×–2×).

## Установка (Arch Linux)

```
git clone https://github.com/vugsk/nuncio-linux-gui-app.git
cd nuncio-linux-gui-app/packaging/arch && makepkg -si
```

PKGBUILD собирает последний коммит этого репозитория; FFmpeg, OpenSSL, шрифт эмодзи и
бинарники Skia скачивает `makepkg` и сверяет по SHA-256 (подпись FFmpeg — по отпечатку
ключа). Ставятся `/usr/bin/nuncio`, пункт меню, значок, примеры тем
(`/usr/share/nuncio/themes`) и тексты лицензий.

Нужна служба Secret Service (GNOME Keyring, KWallet или KeePassXC с интеграцией);
по желанию — `xdg-desktop-portal` (выбор файлов), `sound-theme-freedesktop` (звук
уведомлений).

## Первый запуск: свой api_id

Ключи API выдаёт https://my.telegram.org (API development tools). Положите их в
`~/.config/nuncio/api.env` (права 0600):

```
API_ID=123456
API_HASH=0123456789abcdef0123456789abcdef
```

## Файлы

| Где | Что |
|---|---|
| `~/.config/nuncio/` | `api.env`, `config.toml` (настройки, прокси) |
| `~/.local/share/nuncio/` | база сообщений (SQLite), зашифрованный файл сессии |
| `~/.cache/nuncio/` | вложения, аватарки (лимит — в настройках) |
| `~/.local/state/nuncio/` | журналы: только счётчики и шаги, без содержимого |

Учитываются `XDG_*_HOME`. «Выйти из аккаунта» удаляет сессию, ключ, базу и кэш.

## Своя тема

Пример со всеми ключами и пояснениями — `themes/polar-night.toml`. Настройки →
Внешний вид → «Из файла»; правки файла применяются на лету, ошибки видны там же.

## Сборка из исходников

Нужны: Rust, Go, CMake, Meson + Ninja, компилятор C++20, `clang`, `nasm`, `protoc` + `protoc-gen-go`,
`just`, Python 3; для `just lint` ещё `cargo-deny`, `staticcheck`, `clang-tidy`.

```
just deps    # шаг 0: OpenSSL, FFmpeg, ThorVG, шрифт эмодзи (third_party/deps.toml, SHA-256)
just build   # tl, core, proto, net, cargo build
just test    # ядро (и под ASan/UBSan), go test -race, cargo test
just lint    # clippy, cargo deny, лицензии Go, Skia по SHA-256, PKGBUILD ↔ deps.toml, go vet, staticcheck, clang-tidy
just e2e     # сквозные проверки под Xvfb против поддельного сервера Telegram
```

После смены `proto/client.proto` — `just proto` и `just net` перед `cargo build`.

`just e2e` ждёт Xvfb на `:99` (`Xvfb :99 -screen 0 4200x2400x24 -nolisten tcp`).
Проверки работают с синтетическими данными: поддельный сервер (`net/cmd/fakeserver`),
своя шина D-Bus с поддельными уведомлениями и треем (`net/cmd/fakedesk`); на рабочий
стол, в браузер и на колонки ничего не попадает.

## Устройство репозитория

| Каталог | Что |
|---|---|
| `app/` | исполняемый файл: поток домена, связка слоёв |
| `domain/` | модель приложения, база, настройки — без интерфейса и сети |
| `ui/` | разметка Slint, отрисовка, своя раскладка текста с эмодзи |
| `bridge/` | стык Rust ↔ Go (protobuf, C ABI) |
| `player/` | воспроизведение видео и звука (FFmpeg, cpal) |
| `net/` | сеть на Go: MTProto, вход, обновления, файлы, D-Bus (уведомления, трей, порталы) |
| `core/` | крипто-ядро на C++ (AES-IGE, DH, RSA, SRP, конверты MTProto) |
| `proto/`, `schema/` | `client.proto`; схема TL (слой 229) и корни генерации |
| `tools/` | генератор TL-кодека, проверки лицензий и сторонних бинарников |
| `third_party/` | `deps.toml` (версии и суммы), `fetch_deps.py`, `NOTICES.md` |
| `packaging/`, `themes/` | PKGBUILD, `.desktop`, значок; примеры тем |
| `tests/` | сквозные проверки и замеры |

## Документация

Архитектура, дизайн экранов, решения и протоколы проверок ведутся отдельно, в
личном хранилище заметок автора, и в репозиторий не входят. Что нужно для сборки и
работы с кодом — в этом README, комментариях к коду и `third_party/NOTICES.md`.
